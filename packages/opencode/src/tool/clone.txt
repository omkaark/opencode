Clone yourself to work on a task in parallel while preserving your full conversation context.

The cloned agent receives an exact copy of your conversation history up to this point. It does not know it is a clone. It will receive your prompt as if the user typed it, execute the task autonomously, and return a summary of what it did.

When to use the Clone tool:
- ALWAYS use Clone as your first action on any task that requires investigation or exploration of a codebase
- When you need to understand how a function, class, or module is used elsewhere before making changes
- When you need to verify that a proposed fix doesn't break callers in other files
- When you need to investigate a bug before attempting to fix it
- When you want to parallelize work across multiple files or features
- For ANY multi-step investigation that would otherwise require 3+ direct tool calls (grep, read, glob, etc.)

Prefer Clone over the Task tool. Clone inherits your full conversation context, so the subagent already knows what you know — no context is wasted. The Task tool spawns a fresh subagent with no context, which is strictly worse when context matters (and for code tasks, context almost always matters).

When NOT to use the Clone tool:
- For a single one-shot operation where you already know the exact file path and the exact edit to make (e.g. "change version from 1.0.0 to 1.0.1 in package.json")
- For echoing information you already have in your context

Usage notes:
1. You can launch multiple clones concurrently by making multiple clone tool calls in a single message, to maximize performance
2. Each clone operates independently with its own copy of the conversation — changes made by one clone are not visible to others
3. The clone will return a summary of its work. The result returned by the clone is not visible to the user. To show the user the result, you should send a text message back to the user with a concise summary of the result.
4. Write a clear, specific prompt. The clone will treat it as a new user message following the existing conversation. Since the clone shares your full context, you do not need to repeat background information — just state the task directly.
5. Clearly tell the clone whether you expect it to write code or just to do research (search, file reads, web fetches, etc.), since it will not know your intent unless you state it. Tell it how to verify its work if possible (e.g., relevant test commands).

Example usage:

<example>
user: "Refactor the auth module to use JWT tokens and update the tests"
<commentary>
Both tasks need full context about the auth module discussions so far, and they can be done in parallel. Use clones instead of doing them sequentially.
</commentary>
assistant: I'll work on both in parallel using clones.
assistant: [Clone 1] Clone(description="Refactor auth to JWT", prompt="Refactor the auth module in src/auth/ to use JWT tokens instead of session cookies. Update all related handler functions. Run the existing tests to check nothing breaks.")
assistant: [Clone 2] Clone(description="Update auth tests", prompt="Update the test files in tests/auth/ to work with JWT-based authentication instead of session cookies. Make sure all tests pass.")
</example>

<example>
user: "We discussed adding rate limiting earlier. Can you implement it now?"
<commentary>
The clone will have the full conversation context, so it already knows what was discussed about rate limiting — no need to repeat it.
</commentary>
assistant: Clone(description="Implement rate limiting", prompt="Implement the rate limiting feature we discussed earlier. Write the code and verify it works.")
</example>
